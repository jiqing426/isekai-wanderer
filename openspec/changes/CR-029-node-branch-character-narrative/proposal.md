# CR-029 Proposal: 节点分支标记与角色专属叙事

## 为什么做

当前叙事引擎所有角色共享同一套节点，无法实现"不同角色看到不同剧情分支，最终汇合到共同节点"的分支-汇合叙事结构。这是乙女游戏的核心叙事能力，直接影响玩家沉浸感和角色代入感。

**业务目标**：
- 提升角色专属感和沉浸感（每个角色有独特剧情体验）
- 支持分支-汇合叙事结构（降低多路线维护成本）
- 为后续多结局、角色专属事件奠定基础

## 变更内容

### 1. 数据库扩展
- `nodes` 表新增 `character_id` 字段（UUID，可空）
  - NULL = 公共节点（所有角色可见）
  - 非NULL = 分支节点（仅该角色可见）
- 创建索引 `ix_nodes_character_id`

### 2. 后端叙事引擎改造
- `NarrativeEngine.get_next_node()` 根据 `session.character_id` 过滤节点
- 只返回 `character_id` 为 NULL 或匹配当前角色的节点
- 向后兼容：`session.character_id` 为 NULL 时走原逻辑

### 3. 数据填充（MVP 聚焦 1 个剧本）
- 为 MVP 剧本创建分支-汇合节点数据：
  - 分支起点（公共）
  - 角色A/B/C 专属分支（各角色可见）
  - 汇合点（公共）
- 选择项数量从 2 个改为 3 个

### 4. 前端（无需改动）
- 节点过滤在后端完成，前端透明消费

## 不做范围

- ❌ 全量 3 个剧本的分支节点数据（CEO 条件：先聚焦 1 个剧本 MVP）
- ❌ 多结局系统（后续 CR）
- ❌ 角色专属 CG/立绘（后续 CR）
- ❌ 分支选择历史记录页面（后续 CR）
- ❌ 前端节点编辑器可视化分支预览（后续 CR）

## 成功标准

- 分支可见性：不同角色看到不同分支内容，选择角色A/B/C分别调用API返回节点不同
- 汇合一致性：分支结束后汇合到相同节点，三个角色完成分支后调用API返回相同汇合节点
- 向后兼容：现有session正常运行，无character_id的旧session继续游戏无异常
- 选择项数量：选择节点显示3个选项，到达选择节点时前端展示3个选项

| 指标 | 目标 | 验证方式 |
| --- | --- | --- |
| 分支可见性 | 不同角色看到不同分支内容 | 选择角色A/B/C，分别调用 API，返回节点不同 |
| 汇合一致性 | 分支结束后汇合到相同节点 | 三个角色完成分支后，调用 API 返回相同汇合节点 |
| 向后兼容 | 现有 session 正常运行 | 无 character_id 的旧 session 继续游戏无异常 |
| 选择项数量 | 选择节点显示 3 个选项 | 到达选择节点时，前端展示 3 个选项 |
