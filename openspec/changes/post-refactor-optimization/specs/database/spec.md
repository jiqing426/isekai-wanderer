# Database Spec — CR-008 V2

## 需求概述

修复数据格式问题，统一使用 UUID v4 标准。

## 需求列表

### REQ-BUG-017: script_id 改为 UUID v4（P1）

**场景 1**: 数据迁移
- 现有 `script_id` 从其他格式（如整数、短字符串）迁移到 UUID v4
- 迁移脚本自动执行
- 迁移过程中保持数据完整性

**场景 2**: 前后端兼容
- 前端接口调用使用新的 UUID v4 格式
- 后端接口接收和返回 UUID v4 格式
- 数据库字段类型调整为 `UUID` 或 `VARCHAR(36)`

**场景 3**: 外键关联
- 所有关联 `script_id` 的表同步更新
- 包括：`script_stats`、`script_tags`、`user_scripts` 等
- 外键约束保持正确

**场景 4**: 回滚方案
- 迁移前备份数据
- 提供回滚脚本
- 回滚后数据恢复到迁移前状态

**验收标准**:
- AC-017-1: 所有 `script_id` 字段使用 UUID v4 格式
- AC-017-2: 数据迁移完成，现有数据兼容
- AC-017-3: 前后端接口正常
- AC-017-4: 外键关联正确
- AC-017-5: 提供回滚方案

**数据迁移影响评估**:
- 受影响表：`scripts`、`script_stats`、`script_tags`、`user_scripts`、`user_script_progress`
- 预计数据量：scripts 表 ~100 条，关联表 ~1000 条
- 迁移时间：预计 < 1 分钟
- 停机要求：需要短暂停机（< 5 分钟）

**迁移步骤**:
1. 备份所有受影响表
2. 停止应用服务
3. 执行迁移脚本
4. 验证数据完整性
5. 重启应用服务
6. 验证功能正常

## 依赖

- BE: 需要编写迁移脚本
- BE: 需要更新所有相关接口
- FE: 需要确认前端接口调用正常

## 风险

- 数据迁移失败导致数据丢失
- 外键关联错误导致数据不一致
- 停机时间过长影响用户体验
- 回滚失败导致无法恢复

## 缓解措施

- 迁移前完整备份
- 在测试环境验证迁移脚本
- 准备详细的回滚文档
- 选择低峰期执行迁移
