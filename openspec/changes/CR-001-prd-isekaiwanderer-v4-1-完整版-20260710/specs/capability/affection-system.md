# S004 好感度系统（基础版）

## REQ-004: 好感度系统

### 需求概述

角色养成核心循环。好感度 5 等级（相识→暧昧→信赖→羁绊→挚爱），0-100 数值化，每次互动变化 ≤±5，半隐藏进度条展示。

### Requirement: 好感度计算

**ID**: REQ-004-R01  
**优先级**: P0  

玩家每次与角色互动（对话选择、剧情选择）后，系统根据选项的预设好感度变化值更新该角色的好感度。单次变化范围 ≤±5。

#### Scenario: 玩家选择一个增加好感度的选项

- **Given** 玩家当前与角色 A 好感度为 35（相识级），选择了一个好感度 +3 的选项
- **When** 系统处理选择结果
- **Then** 角色 A 好感度更新为 38，如果达到等级阈值则升级等级

#### Scenario: 玩家选择一个降低好感度的选项

- **Given** 玩家当前与角色 A 好感度为 50（暧昧级），选择了一个好感度 -2 的选项
- **When** 系统处理选择结果
- **Then** 角色 A 好感度更新为 48

#### Scenario: 好感度达到等级阈值时升级

- **Given** 角色 A 好感度从 19 变为 20（相识→暧昧阈值）
- **When** 好感度更新完成
- **Then** 等级从"相识"升级为"暧昧"，触发升级动画或提示

### Requirement: 好感度等级体系

**ID**: REQ-004-R02  
**优先级**: P0  

好感度分为 5 个等级，每个等级对应一个数值区间：

| 等级 | 数值范围 | 标签 |
| --- | --- | --- |
| 1 | 0-19 | 相识 |
| 2 | 20-39 | 暧昧 |
| 3 | 40-59 | 信赖 |
| 4 | 60-79 | 羁绊 |
| 5 | 80-100 | 挚爱 |

#### Scenario: 查看角色好感度等级

- **Given** 玩家与角色 A 好感度为 65
- **When** 玩家打开角色信息页
- **Then** 显示"羁绊"等级标签和进度条

### Requirement: 半隐藏进度条展示

**ID**: REQ-004-R03  
**优先级**: P0  

好感度进度条为半隐藏设计：默认显示等级标签和模糊进度（如进度条不显示精确数值），玩家主动点击可展开查看详细数值。

#### Scenario: 默认展示好感度等级

- **Given** 玩家在游戏界面中
- **When** 角色好感度发生变化
- **Then** 界面显示等级标签（如"信赖"）和进度条动画，但不显示精确数值

#### Scenario: 玩家点击查看详细好感度

- **Given** 玩家点击好感度进度条区域
- **When** 展开详情
- **Then** 显示精确数值（如"45/59"）和距下一等级的差距

### 不做范围（本 CR）

- 不做 CG 解锁联动（S004-BOND-F01.03，CG 跟随好感度但无独立解锁事件）
- 不做好感度等级对应的称呼/对话变化（见 Q-007，建议 MVP 不做）
- 不做好感度重置功能

### R/C/U/D 完整性

| 动作 | 是否包含 | 说明 |
| --- | --- | --- |
| Create | 是 | 首次与角色互动时初始化好感度记录 |
| Read | 是 | 展示好感度等级和进度 |
| Update | 是 | 每次互动后更新好感度数值 |
| Delete | 否 | MVP 不删除好感度记录 |

### 下游约束

- 需要 DB 契约：好感度存储结构（用户ID、角色ID、数值、等级、更新时间）
- 需要 API 契约：好感度查询、好感度变更接口
- 验收需要真实后端验证：好感度持久化、等级计算正确性
- 验收需要浏览器交互：进度条展示、展开/收起交互
