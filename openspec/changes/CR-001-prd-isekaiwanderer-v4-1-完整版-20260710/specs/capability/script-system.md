# S002 结构化剧本系统

## REQ-002: 结构化剧本系统

### 需求概述

支持多路线、多结局的结构化剧本体验。MVP 交付 3 个剧本（已确认，见 Q-001）：
- **乙女恋爱**（主力剧本）：3 条角色路线 × 2-3 个结局（好/普通/坏）
- **奇幻冒险**（轻量剧本）：2 条角色路线 × 2 个结局（好/普通）
- **悬疑推理**（轻量剧本）：2 条角色路线 × 2 个结局（好/普通）

### Requirement: 剧本路线管理

**ID**: REQ-002-R01  
**优先级**: P0  

系统必须支持剧本 → 路线 → 节点的三层结构。玩家进入剧本后选择路线，路线内通过选择点影响剧情走向和结局。

#### Scenario: 玩家进入剧本并选择路线

- **Given** 玩家已登录，剧本可用
- **When** 玩家在剧本首页点击"开始游戏"，选择某条角色路线
- **Then** 系统加载该路线的起始节点，展示第一个场景和对话

#### Scenario: 玩家做出影响剧情的选择

- **Given** 玩家处于选择点节点，有 2-4 个选项
- **When** 玩家选择某选项
- **Then** 系统根据选项的后续节点 ID 跳转，同时更新好感度和选择历史

### Requirement: 收敛节点设计

**ID**: REQ-002-R02  
**优先级**: P0  

剧本必须包含收敛节点：多条分支在关键剧情点汇合，确保叙事可控。收敛节点后的分支由累积选择（而非单次选择）决定。

#### Scenario: 多条分支在收敛节点汇合

- **Given** 某路线在关键章节有多条分支
- **When** 玩家完成任意分支
- **Then** 系统将所有分支收束到收敛节点，根据累积好感度和选择历史决定后续分支

### Requirement: 结局触发

**ID**: REQ-002-R03  
**优先级**: P0  

每条路线有 2-3 个结局（好/普通/坏），结局由累积好感度和关键选择触发。结局页面展示结局类型、剧情总结、解锁的 CG（如有）。

#### Scenario: 玩家达成好结局

- **Given** 路线结束时角色好感度 ≥80（羁绊级）且关键选择正确
- **When** 玩家完成最后一个节点
- **Then** 系统展示好结局页面，包含结局剧情、角色独白、解锁 CG 展示

#### Scenario: 玩家达成坏结局

- **Given** 路线结束时角色好感度 <40 或关键选择错误
- **When** 玩家完成最后一个节点
- **Then** 系统展示坏结局页面，提供"重新开始本路线"按钮

### Requirement: 路线探索展示

**ID**: REQ-002-R04  
**优先级**: P1  

剧本完成后展示路线探索图，显示已探索分支和未探索分支（灰色锁定），引导玩家多周目体验。

#### Scenario: 玩家查看路线探索图

- **Given** 玩家已完成某路线的好结局
- **When** 玩家在剧本详情页点击"路线探索"
- **Then** 系统展示路线图，已探索分支高亮，未探索分支灰色并显示解锁条件提示

### R/C/U/D 完整性

| 动作 | 是否包含 | 说明 |
| --- | --- | --- |
| Create | 是 | 剧本/路线/节点的创建（内容录入） |
| Read | 是 | 玩家读取剧本进度、路线状态 |
| Update | 是 | 玩家进度更新、节点状态变更 |
| Delete | 否 | MVP 不删除剧本数据，仅重置进度 |

### 下游约束

- 需要 DB 契约：剧本/路线/节点/玩家进度的数据模型
- 需要 API 契约：剧本列表、路线详情、进度保存/读取
- 验收需要真实后端验证：进度持久化、分支跳转逻辑
- 验收需要浏览器交互：选择点操作、结局触发、路线探索图查看
