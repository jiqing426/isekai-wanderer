## 七、风险与建议

### 主要风险

1. **工时超支** — 剩余工作量较大（60 天），可能超出预期
2. **技术复杂度** — W06 重构 + 动态对话额度 + 碎片经济系统复杂度较高
3. **依赖关系** — 多个页面依赖后端 API，需要协调 FE/BE 进度
4. **测试覆盖** — 需要大量测试确保功能正确性

### 建议

1. **分阶段交付** — 先完成 P0（W05/W06/W07/W09），再完成 P1，最后 P2
2. **并行开发** — FE 和 BE 并行开发，减少等待时间
3. **优先级调整** — 如果时间紧张，可以推迟 P2 到后续迭代
4. **增加资源** — 考虑增加 FE/BE 人员，加快开发进度
5. **MVP 策略** — 先实现核心功能，后续迭代补充高级功能
