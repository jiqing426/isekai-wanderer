# CR-029: 节点分支标记与角色专属叙事

- 目标：实现分支-汇合叙事结构，nodes 表新增 character_id 字段，NarrativeEngine 按角色过滤节点，不同角色看到不同分支内容并最终汇合到公共节点
- 成功标准：不同角色看到不同分支内容；分支结束后汇合到相同节点；现有 session 正常运行无异常；选择节点显示 3 个选项

## 变更概述

实现分支-汇合叙事结构：不同角色进入不同对话分支，最终汇合到共同节点。

## 需求描述

### 1. 数据库改动

`nodes` 表新增 `character_id` 字段：
- NULL = 所有角色可见（公共节点）
- 非NULL = 仅该角色可见（分支节点）

### 2. 后端改动

`NarrativeEngine` 节点过滤逻辑：
- 根据 `session.character_id` 过滤可见节点
- 只返回 `character_id` 为 NULL 或匹配当前角色的节点

### 3. 前端改动

无需改动（节点过滤在后端完成）

### 4. 数据填充

为每个剧本创建角色分支节点：
- 分支起点（公共）
- 角色A分支（仅A可见）
- 角色B分支（仅B可见）
- 角色C分支（仅C可见）
- 汇合点（公共）

### 5. 选择项数量

从2个改为3个：
- 修改节点数据，插入第3个选项

## 预期效果

```
起始节点 (所有角色)
    ↓
┌─────────────┬─────────────┐
↓             ↓             ↓
角色A分支    角色B分支    角色C分支
    ↓             ↓             ↓
    └─────────────┴─────────────┘
                  ↓
            汇合节点 (所有角色)
```

## 目标

实现分支-汇合叙事结构：不同角色进入不同对话分支，最终汇合到共同节点。提升角色专属感和沉浸感。

## 成功标准

| 指标 | 目标 | 验证方式 |
| --- | --- | --- |
| 分支可见性 | 不同角色看到不同分支内容 | 选择角色A/B/C，分别调用 API，返回节点不同 |
| 汇合一致性 | 分支结束后汇合到相同节点 | 三个角色完成分支后，调用 API 返回相同汇合节点 |
| 向后兼容 | 现有 session 正常运行 | 无 character_id 的旧 session 继续游戏无异常 |
| 选择项数量 | 选择节点显示 3 个选项 | 到达选择节点时，前端展示 3 个选项 |
