# Production Checklist

生产发布前必须逐项确认。本文件记录通用工程检查，不替代具体项目的发布流程。

## 发布前

- 已确认本次发布范围、版本号、负责人和回滚负责人。
- 已运行必要的构建、测试、迁移预检和安全检查。
- 已确认 `docs/operations/operations.md` 中的环境变量、健康检查和依赖服务仍然有效。
- 已确认数据库迁移可回滚或已记录不可回滚风险。
- 已确认没有真实密钥、调试开关、测试账号或生产数据样本进入仓库。
- 已确认监控、日志、告警和错误追踪可观察本次变更。

## 发布中

- 按既定顺序发布后端、前端、管理端和任务进程。
- 先验证健康检查，再放量用户流量。
- 涉及数据库迁移时，确认应用版本与迁移版本兼容。
- 涉及权限、支付、数据导出或批量操作时，执行拒绝路径验证。

## 部署前 — Docker 验证

- [ ] 每个服务都有对应的 `Dockerfile`（backend、frontend、admin 如适用）
- [ ] `docker compose build` 成功，无构建错误
- [ ] `docker compose up -d` 成功，所有健康检查通过
- [ ] `docker compose ps` 显示所有服务 Up 且 Healthy
- [ ] 后端健康检查返回 200：`curl http://localhost:<BACKEND_PORT>/health`
- [ ] 前端页面可访问：`curl http://localhost:<FRONTEND_PORT>/` 返回 HTML

## 部署后 — E2E 冒烟验证

- [ ] 运行 `tests/e2e/smoke.test.ts`，所有用例通过
- [ ] E2E 测试使用 `APP_BASE` 和 `API_BASE` 环境变量，不硬编码端口
- [ ] E2E 报告必须分类统计（API 集成 / 前端渲染 / 前端交互），不得仅写"N/N 通过"

## 发布后

- 验证关键用户路径、管理端路径和后台任务。
- 检查错误率、延迟、资源使用率和业务关键指标。
- 检查日志中没有敏感信息泄露。
- 更新 `docs/status/feature-status.md`、发布记录或变更说明。

## 回滚

- 明确可回滚制品版本。
- 明确数据库、队列、缓存和对象存储的回滚或补偿方式。
- 回滚后重新验证健康检查、关键路径和数据一致性。
