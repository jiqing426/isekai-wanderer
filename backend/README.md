# Backend

## 模块职责

`backend/` 负责服务端能力，包括 API、领域逻辑、认证授权、数据访问、任务队列、文件处理、第三方集成和数据库迁移。

不得把后端领域规则复制到 `frontend/` 或 `admin/`。客户端可以做交互校验，但最终业务判定必须以服务端为准。

## 启动方式

推荐通过统一脚本启动：

```sh
../scripts/dev.sh backend
```

项目落地后，应在本模块补充实际命令，例如 `npm run dev`、`make dev`、`uv run`、`go run` 或框架等价命令。

## 目录约定

- `src/`：后端源代码。
- `tests/`：模块内单元测试和轻量集成测试。
- `migrations/`：数据库迁移脚本，若项目使用数据库。
- `docs/`：仅放后端模块内部说明；跨模块事实写入根部 `docs/`。

未使用的目录可以暂不创建，但创建后必须补充 README 或等价说明。

## 开发规范

- API 契约变化同步 `../docs/api/api.md`。
- 表结构、索引、迁移和数据保留策略变化同步 `../docs/database/database.md`。
- 鉴权、授权、审计和数据归属校验必须在服务端实现。
- 不在代码、测试、日志或文档中写入真实密钥和生产数据。
- 不从前端或管理端倒推业务规则；不确定时先更新项目事实或发起确认。

## 测试方式

推荐通过统一脚本运行：

```sh
../scripts/test.sh backend
```

涉及 API、数据库、权限或任务队列的修改，应补充对应的单元测试、集成测试或契约测试。
