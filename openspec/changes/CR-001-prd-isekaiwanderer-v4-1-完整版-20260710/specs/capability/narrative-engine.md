# S001 叙事一致性引擎

## REQ-001: 叙事一致性引擎

### 需求概述

构建"剧情节点 + 状态机 + 角色性格约束"三层防护体系，确保 AI 生成的对话和叙事内容不会偏离剧本设定、不出现人设崩塌。关键剧情节点 100% 人工预设，AI 仅负责节点间对话细节生成。

### Requirement: 剧情节点预设

**ID**: REQ-001-R01  
**优先级**: P0  

系统必须支持人工预设关键剧情节点，每个节点包含：节点 ID、所属剧本、所属路线、触发条件（前置节点 + 好感度阈值 + 选择历史）、节点内容模板、AI 生成约束（角色性格标签、情绪范围、禁止话题）。

#### Scenario: 编剧预设一个剧情分支节点

- **Given** 编剧在剧本"乙女恋爱"路线 A 中设定了一个分支节点 N-015
- **When** 玩家在游戏中满足该节点触发条件（前置节点 N-014 已完成 + 角色 A 好感度 ≥60 + 选择了选项 2）
- **Then** 系统按预设内容展示该节点，AI 不得修改节点核心剧情

#### Scenario: AI 在两个预设节点之间生成过渡对话

- **Given** 玩家刚完成节点 N-010，下一预设节点 N-015 尚未触发
- **When** 玩家与角色进行对话互动
- **Then** AI 根据角色性格标签和当前上下文生成过渡对话，内容不得涉及 N-015 的剧情事件

### Requirement: 规则引擎校验

**ID**: REQ-001-R02  
**优先级**: P0  

系统必须在 AI 生成内容输出前进行规则校验，包括：角色性格一致性检查（不允许角色说出与设定矛盾的话）、时间线一致性检查（不允许提到未发生的事件）、好感度范围检查（好感度低时不出现亲密称呼）。

#### Scenario: AI 生成内容违反角色性格约束

- **Given** 角色 A 的性格标签为"冷淡/理性"，当前好感度为 25（相识级）
- **When** AI 生成了一句包含亲昵称呼"亲爱的"的对话
- **Then** 规则引擎拦截该输出，触发兜底机制重新生成

#### Scenario: AI 生成内容引用了未发生的事件

- **Given** 当前剧情进度尚未到达"角色 A 身世揭秘"节点
- **When** AI 生成对话中提到角色 A 的身世秘密
- **Then** 规则引擎拦截该输出，触发兜底机制重新生成

### Requirement: 兜底机制

**ID**: REQ-001-R03  
**优先级**: P0  

当 AI 生成内容被规则引擎拦截时，系统必须有兜底机制：自动重新生成（最多 2 次重试），若仍不通过则使用预设兜底对话（每个节点至少 1 条兜底对话）。用户不得感知到系统错误或空白内容。

#### Scenario: AI 连续生成失败，使用兜底对话

- **Given** AI 在节点 N-010 与 N-015 之间的过渡对话生成
- **When** 连续 2 次生成均被规则引擎拦截
- **Then** 系统使用预设兜底对话展示给用户，用户看到正常对话内容，无空白或错误提示

### 不做范围（本 CR）

- 不做情感节奏控制系统（S008，P1）
- 不做 AI 风格化对话系统（S009，P1）
- 不做自由对话模式

### R/C/U/D 完整性

| 动作 | 是否包含 | 说明 |
| --- | --- | --- |
| Create | 是 | 预设剧情节点的创建 |
| Read | 是 | 运行时读取节点配置和约束规则 |
| Update | 是 | 预设节点可修改（内容迭代） |
| Delete | 否 | MVP 不删除节点，仅标记为禁用 |

### 下游约束

- 需要 API/DB 契约：节点数据结构、触发条件模型、AI prompt 模板存储
- 需要 AI 集成：LLM prompt 工程、规则引擎与 LLM 输出的串联流程
- 验收需要真实后端验证：AI 生成 → 规则校验 → 兜底 全链路
