# CR-027: 分层 Prompt 叙事引擎系统

## 为什么做

当前叙事引擎（`NarrativeEngine`）存在以下问题：
1. **Prompt 结构混乱**：各层信息（全局规则、世界观、NPC、记忆、导演指令）混在一起，难以维护和调试
2. **无世界知识库**：世界观信息硬编码在 Prompt 或剧本中，无法动态管理和复用
3. **NPC 人设扁平**：只有基础 traits/likes/speak_style，缺少内在驱动（渴望/恐惧/秘密）
4. **无 Token 预算控制**：Prompt 长度不可控，容易超出模型上下文窗口或浪费 Token
5. **场景配置缺失**：场景信息（氛围/标签）无法动态注入 Prompt

升级为分层 Prompt 系统可解决以上问题，实现：
- 可维护：六层结构清晰分离，各层独立演进
- 可扩展：Lorebook 支持动态世界知识管理
- 可控制：Token 预算确保不超限
- 可差异化：NPC 内在驱动让角色更立体

## 变更内容

- Lorebook 世界知识库：基础 CRUD + 场景标签注入
- 场景配置系统：基础场景-标签绑定
- NPC 人物内核扩展：新增渴望/恐惧/秘密字段
- Prompt 拼接引擎：六层结构化拼接
- Token 预算控制器：2300 tokens 上限，各层预算分配
- 前端管理界面：Lorebook/场景/NPC 管理（最小可用）

## 不做范围

- Lorebook 智能检索优化（MVP 用简单标签匹配）
- 动态记忆向量检索增强（依赖向量数据库选型）
- 多语言 Prompt
- Prompt 可视化编辑器
- Token 用量统计与计费

## 成功标准

- Prompt 六层结构清晰分离，各层可独立测试
- Lorebook CRUD 可用，场景标签注入正常
- NPC 渴望/恐惧/秘密字段可配置，注入 Prompt 后角色行为更立体
- Token 总预算控制在 2300 以内，各层不超限
- 前端管理界面可完成基础配置

## 影响范围

- 数据库：新增 lorebook_entries、scene_configs 表；Character 表新增 desire/fear/secret 字段
- 后端：新增 LorebookService、SceneConfigService、PromptBuilder、TokenBudgetController
- 前端：新增 Lorebook 管理页、场景配置页、NPC 编辑页
- API：新增 Lorebook/Scene/NPC 相关接口
- 现有 NarrativeEngine 需重构 Prompt 构建逻辑
