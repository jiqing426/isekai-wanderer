# CR-030: 章节结构重构

## 变更目标

实现剧本的4章节结构（相遇/日常/冲突/收束），替代当前的纯route结构，使剧本组织更符合文档规范。

- 目标：为 routes 表新增章节字段，实现 4 章节叙事结构，API 返回章节信息，前端进度条展示章节名
- 成功标准：数据库迁移成功、11 条 route 正确映射到章节、API 返回章节信息、前端展示章节名、旧 session 向后兼容

## 影响范围

- [x] 后端（BE）— 数据库迁移、API改动
- [x] 前端（FE）— 章节展示、进度条
- [x] 数据库（DB）— routes表新增字段
- [ ] 运维（Ops）

## 优先级

P0 - 基础结构重构，后续优化依赖此项

## 需求描述

### 1. 数据库改动

`routes` 表新增章节字段：
```sql
ALTER TABLE routes ADD COLUMN chapter_number INTEGER;
ALTER TABLE routes ADD COLUMN chapter_type VARCHAR(50);
-- chapter_type: encounter/daily/conflict/convergence
```

### 2. 数据迁移

将现有route按章节规则重新组织：
- 星月奇缘：3条路线 → 映射到3个章节
- 星辰之约：4条路线 → 映射到4个章节
- 樱花恋曲：4条路线 → 映射到4个章节

### 3. 后端改动

- `/game/{session_id}/status` 返回当前章节信息
- `/scripts/{id}/chapters` 返回剧本章节列表
- 进度计算基于章节而非route

### 4. 前端改动

- 进度条显示"第X章：章节名"
- 章节切换时显示过渡动画
- 章节选择界面（可选）

## 预期效果

```
剧本：星月奇缘
├── 第1章：相遇（route: 第一章：月夜邂逅）
├── 第2章：日常（route: 第二章：星辰之约）
└── 第3章：冲突（route: 第三章：命运交织）
```
