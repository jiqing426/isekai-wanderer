# Spec: 每日任务系统增强（P1）

### Requirement: REQ-TASK-001 每日任务列表

#### 需求描述
用户在首页可查看每日任务列表，展示当日可完成的任务。任务每天 UTC 00:00 刷新。复用现有 `daily_tasks` 表，扩展 `activity_points` 字段。

#### Scenario: 每日任务列表场景

| ID | Scenario | Given | When | Then |
|----|---------|-------|------|------|
| AC-TASK-001.1 | 查看任务列表 | 用户已登录 | 访问首页或 `/daily` | 显示任务面板，列出当日 3-5 个任务，每行含：任务图标 + 任务描述 + 进度 (X/Y) + 奖励碎片数 |
| AC-TASK-001.2 | 任务类型展示 | 用户查看任务列表 | 查看各任务 | 任务类型包括：①玩一个章节 ②完成一次签到 ③给角色送一次礼物 ④观看一次对话预览 ⑤完成一次存档操作 |
| AC-TASK-001.3 | 任务进度更新 | 用户完成"玩一个章节" | 章节结束时 | 任务进度从 0/1 变为 1/1，状态变为"可领取" |
| AC-TASK-001.4 | 领取任务奖励 | 任务状态为"可领取" | 点击"领取"按钮 | 碎片余额增加，`fragment_transactions` 新增记录，任务状态变为"已领取" |
| AC-TASK-001.5 | 每日刷新 | UTC 00:00 过后 | 用户访问首页 | 任务列表重置为新任务，昨日未完成的任务进度清零 |
| AC-TASK-001.6 | 全部完成奖励 | 用户完成当日所有任务 | 最后一个任务领取后 | 显示"🎉 今日任务全部完成！额外奖励 +25 碎片"+ 活跃度加成提示 |

### 任务类型定义

| 任务类型 | 描述 | 目标数 | 碎片奖励 | 活跃度 |
|---------|------|--------|---------|--------|
| `play_chapter` | 玩一个章节 | 1 | +10 | +10 |
| `daily_checkin` | 完成签到 | 1 | +5 | +5 |
| `send_gift` | 给角色送礼物 | 1 | +5 | +5 |
| `view_dialogue` | 观看对话预览 | 1 | +5 | +5 |
| `save_operation` | 完成存档操作 | 1 | +5 | +5 |

### 任务刷新约束
- 刷新时间：UTC 00:00（与 `daily_checkins` 一致）
- 任务列表由 BE 配置种子数据，前端不硬编码
- 未完成的任务不跨日累积

## REQ-TASK-002: 任务进度条

### 需求描述
显示用户当日任务完成进度条，完成全部任务获额外碎片奖励。

### Scenarios

| ID | Scenario | Given | When | Then |
|----|---------|-------|------|------|
| AC-TASK-002.1 | 查看总进度 | 用户已登录 | 查看任务面板顶部 | 显示进度条"已完成 X/Y 个任务"+ 百分比 |
| AC-TASK-002.2 | 进度更新 | 用户完成一个任务 | 领取奖励后 | 进度条实时更新（如从 2/5 变为 3/5） |
| AC-TASK-002.3 | 全部完成 | 用户完成所有任务 | 最后一个任务领取 | 进度条满格（5/5 100%）+ 显示"全部完成！"+25 碎片已发放" |
| AC-TASK-002.4 | 未开始 | 用户当日未做任何任务 | 查看任务面板 | 进度条显示 0/5 (0%) |
| AC-TASK-002.5 | 进度条动画 | 进度更新时 | 进度条变化 | 平滑过渡动画（300ms ease-in-out） |

### 进度条展示约束
- 进度条颜色：0-50% 蓝色，50-99% 紫色，100% 金色
- 百分比显示在进度条右侧
- 全部完成时进度条闪烁金色光效（2 秒）

## REQ-TASK-003: 活跃度宝箱

### 需求描述
用户完成任务获得活跃度，活跃度达到阈值解锁宝箱。宝箱随机获得碎片或道具。新建 `activity_chests` 表记录宝箱状态。

### Scenarios

| ID | Scenario | Given | When | Then |
|----|---------|-------|------|------|
| AC-TASK-003.1 | 查看活跃度进度 | 用户已登录 | 查看任务面板活跃度区域 | 显示活跃度进度条 + 宝箱图标（50/100/150 三个阈值） |
| AC-TASK-003.2 | 活跃度累积 | 用户完成任务获得活跃度 | 任务领取后 | 活跃度进度条增加（如从 10 变为 20） |
| AC-TASK-003.3 | 达到第一阈值 | 活跃度达到 50 | 进度条到达 50 时 | 第一个宝箱图标亮起 + "可领取"标签 + 全局 toast"🎁 活跃度宝箱已解锁！" |
| AC-TASK-003.4 | 领取宝箱 | 宝箱状态为"可领取" | 点击宝箱图标 | 弹出开箱动画（2 秒）+ 显示奖励内容（如"+15 碎片"）+ `activity_chests.claimed=true` |
| AC-TASK-003.5 | 宝箱奖励发放 | 宝箱领取成功 | 奖励发放 | `fragments.balance` 增加，`fragment_transactions` 新增 `type=activity_chest` 记录 |
| AC-TASK-003.6 | 已领取状态 | 宝箱已领取 | 查看宝箱 | 宝箱图标变为灰色 + "已领取"标签 |
| AC-TASK-003.7 | 每日重置 | UTC 00:00 过后 | 新的一天 | 活跃度归零，宝箱状态重置为未解锁 |
| AC-TASK-003.8 | 未达阈值 | 活跃度 < 50 | 查看宝箱 | 宝箱图标灰色 + "还需 X 活跃度"提示 |

### 活跃度阈值与奖励

| 阈值 | 宝箱等级 | 奖励范围 | 图标 |
|------|---------|---------|------|
| 50 | 铜箱 | 10-20 碎片（随机） | 📦 |
| 100 | 银箱 | 20-40 碎片（随机） | 🎁 |
| 150 | 金箱 | 40-80 碎片（随机）+ 稀有称号 | 👑 |

### 宝箱随机算法约束
- 奖励范围由 BE 配置，前端不硬编码
- 随机数生成使用 BE 安全随机（非前端 Math.random）
- 金箱称号奖励从 `achievement_definitions` 中 `reward_type=title` 的池子随机选取
- 同一用户每日每个阈值只能领取一次（`UNIQUE(user_id, date, threshold)`）

### 活跃度与任务关系

| 任务 | 活跃度 | 累计 |
|------|--------|------|
| 完成签到 | +5 | 5 |
| 玩一个章节 | +10 | 15 |
| 送一次礼物 | +5 | 20 |
| 观看对话预览 | +5 | 25 |
| 完成存档操作 | +5 | 30 |
| **全部完成额外** | **+25** | **55** |

**说明**：全部完成可获 55 活跃度，达到第一阈值（50）解锁铜箱。银箱（100）和金箱（150）需要多日累积或特殊活动加成。

## REQ-TASK-004: 任务面板 UI

### 需求描述
任务面板嵌入首页（HomeView），可展开/收起。面板包含任务列表、总进度条、活跃度宝箱三个区域。

### Scenarios

| ID | Scenario | Given | When | Then |
|----|---------|-------|------|------|
| AC-TASK-004.1 | 面板默认状态 | 用户访问首页 | 页面加载 | 任务面板默认收起，显示"每日任务 (X/Y)"标题 + 进度条摘要 |
| AC-TASK-004.2 | 展开面板 | 用户点击面板标题 | 点击 | 面板展开，显示完整任务列表 + 活跃度进度 + 宝箱 |
| AC-TASK-004.3 | 收起面板 | 面板已展开 | 点击标题或空白区 | 面板收起 |
| AC-TASK-004.4 | 任务完成动效 | 用户完成一个任务 | 任务状态变化 | 任务行播放"✓"打勾动画（500ms）+ 碎片飞入动效 |
| AC-TASK-004.5 | 宝箱开启动效 | 用户点击可领取宝箱 | 点击宝箱 | 宝箱摇晃（500ms）→ 打开（1s）→ 金光特效（500ms）→ 显示奖励 |
| AC-TASK-004.6 | 移动端适配 | 用户在移动端 | 查看任务面板 | 面板全屏展示，任务列表垂直排列，宝箱图标横向排列 |

### 面板布局约束

```
┌─────────────────────────────────┐
│ 每日任务 (3/5) ████████░░ 60%   │  ← 标题 + 总进度条
├─────────────────────────────────┤
│ ☑ 玩一个章节        [已领取]    │
│ ☑ 完成签到          [已领取]    │
│ ☑ 送一次礼物        [已领取]    │
│ ☐ 观看对话预览      [领取 +5]   │
│ ☐ 完成存档操作      [领取 +5]   │
├─────────────────────────────────┤
│ 活跃度: 30/50  ██████░░░░       │  ← 活跃度进度条
│ 📦(可领)  🎁(需50)  👑(需100)   │  ← 宝箱图标
└─────────────────────────────────┘
```

## 数据模型需求

| 表 | 用途 | 关键字段 |
|----|------|---------|
| `daily_tasks`（扩展） | 每日任务实例 | +`activity_points INT DEFAULT 0` |
| `activity_chests`（新建） | 活跃度宝箱 | `id`, `user_id FK`, `date DATE`, `threshold INT`, `reward_json JSONB`, `claimed BOOLEAN DEFAULT FALSE`, `claimed_at TIMESTAMPTZ`, `UNIQUE(user_id, date, threshold)` |

### activity_chests 表字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `reward_json` | JSONB | `{"type": "fragments", "amount": 15}` 或 `{"type": "title", "title_code": "ACTIVE_7DAYS"}` |
| `threshold` | INT | 50 / 100 / 150 |
| `claimed` | BOOLEAN | 是否已领取 |
| `claimed_at` | TIMESTAMPTZ | 领取时间（NULL 表示未领取） |

## 路由需求

| 路由 | 用途 | Auth |
|------|------|------|
| `/daily`（可选） | 独立任务页（如不嵌入首页） | Required |

**建议**：任务面板嵌入 HomeView，无需独立路由。如 FE 评估需要独立页，可使用 `/daily`。

## 验收动作标注

- **Browser Interaction E2E**：任务面板展开/收起、任务领取按钮点击、进度条动画、宝箱开启动效，需 Playwright E2E 验证
- **API/DB 验证**：任务领取后 `fragment_transactions` 新增记录、宝箱领取后 `activity_chests.claimed=true`、每日刷新后进度归零，需真实后端状态验证
- **定时任务验证**：UTC 00:00 任务刷新、宝箱状态重置，需 BE 定时任务日志验证
- **随机奖励验证**：宝箱奖励在配置范围内，多次领取不超出范围，需 BE 单元测试覆盖
- **并发验证**：同一用户同时点击多个任务领取，不重复发放奖励，需 BE 幂等性测试

## 与成就系统关联

- 每日任务完成可触发活跃类成就（如"完成 30 个每日任务"）
- 任务领取事件 `task_completed` 会被成就触发器监听
- 活跃度宝箱领取不触发成就（避免循环触发）

## 碎片经济关联

- 任务奖励碎片写入 `fragment_transactions`，类型 `type=daily_task`
- 宝箱奖励碎片写入 `fragment_transactions`，类型 `type=activity_chest`
- 全部完成额外 +25 碎片写入 `fragment_transactions`，类型 `type=daily_bonus`
- 所有碎片奖励在 `/shards` 消费记录中可查
