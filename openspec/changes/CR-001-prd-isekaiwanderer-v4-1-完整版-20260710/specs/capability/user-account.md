# S007 用户账户系统

## REQ-006: 用户账户系统

### 需求概述

基础用户注册/登录系统。MVP 支持邮箱注册/登录（含邮箱验证）+ OAuth mock 登录（Google/Discord，mock 占位，架构预留真实接口，用户后续替换凭证）。注册后 3 步引导：选择偏好 → 推荐剧本 → 开始体验。

### Requirement: 邮箱注册

**ID**: REQ-006-R01  
**优先级**: P0  

用户通过邮箱 + 密码注册账户。注册后发送验证邮件，用户点击验证链接完成激活。未验证用户可登录但功能受限（如无法开始剧本）。

#### Scenario: 新用户注册成功

- **Given** 用户在注册页面
- **When** 用户输入有效邮箱和密码（密码强度 ≥8 位，含字母和数字），点击注册
- **Then** 系统创建账户（状态=未验证），发送验证邮件到该邮箱，页面提示"请查收验证邮件"

#### Scenario: 注册邮箱已存在

- **Given** 邮箱 test@example.com 已被注册
- **When** 用户用该邮箱注册
- **Then** 系统提示"该邮箱已被注册，请登录或使用其他邮箱"

#### Scenario: 注册密码不符合要求

- **Given** 用户在注册页面
- **When** 用户输入密码"123"（不足 8 位）
- **Then** 系统提示"密码至少 8 位，需包含字母和数字"，注册不提交

### Requirement: 邮箱验证

**ID**: REQ-006-R02  
**优先级**: P0  

注册后系统发送含验证链接的邮件，用户点击后账户状态变为已验证。验证链接有效期 24 小时。

#### Scenario: 用户点击验证链接

- **Given** 用户收到验证邮件，链接未过期
- **When** 用户点击验证链接
- **Then** 账户状态变为"已验证"，跳转到登录页并提示"验证成功，请登录"

#### Scenario: 验证链接过期

- **Given** 用户收到的验证邮件已超过 24 小时
- **When** 用户点击验证链接
- **Then** 页面提示"验证链接已过期，请重新发送验证邮件"，提供"重新发送"按钮

### Requirement: 邮箱登录

**ID**: REQ-006-R03  
**优先级**: P0  

用户使用邮箱 + 密码登录。支持"记住我"（7 天免登录）。

#### Scenario: 登录成功

- **Given** 用户已注册且已验证
- **When** 用户输入正确的邮箱和密码，点击登录
- **Then** 登录成功，跳转到游戏首页/上次游玩位置

#### Scenario: 登录失败（密码错误）

- **Given** 用户在登录页面
- **When** 用户输入错误密码
- **Then** 提示"邮箱或密码错误"（不区分邮箱不存在 vs 密码错误，防枚举）

#### Scenario: 未验证邮箱尝试登录

- **Given** 用户已注册但未验证邮箱
- **When** 用户输入正确邮箱和密码登录
- **Then** 登录成功但跳转到"请验证邮箱"页面，提示重新发送验证邮件

### Requirement: OAuth Mock 登录（Google/Discord）

**ID**: REQ-006-R06  
**优先级**: P0  

登录页提供 Google 和 Discord 一键登录按钮。MVP 使用 mock 实现（点击后直接创建/登录 mock 账户），架构预留真实 OAuth 接口，用户后续替换凭证即可切换。

#### Scenario: 用户点击 Google Mock 登录

- **Given** 用户在登录页面
- **When** 用户点击"Continue with Google"按钮
- **Then** 系统使用 mock OAuth 流程创建账户（邮箱=mock-google@example.com），自动登录并跳转到首页
- **And** 页面展示"[Mock] Google 登录"标识，明确非真实 OAuth

#### Scenario: 用户点击 Discord Mock 登录

- **Given** 用户在登录页面
- **When** 用户点击"Continue with Discord"按钮
- **Then** 系统使用 mock OAuth 流程创建账户（邮箱=mock-discord@example.com），自动登录并跳转到首页
- **And** 页面展示"[Mock] Discord 登录"标识，明确非真实 OAuth

#### Scenario: OAuth 接口抽象层可替换

- **Given** 系统 OAuth 模块使用抽象接口（IOAuthProvider）
- **When** 用户后续替换为真实 Google/Discord 凭证
- **Then** 仅需修改配置和实现类，不改架构和调用方代码

### Requirement: 新用户引导

**ID**: REQ-006-R04  
**优先级**: P0  

首次登录的用户经历 3 步引导：①选择偏好（感兴趣的题材类型）→ ②推荐剧本 → ③开始体验。

#### Scenario: 新用户完成引导流程

- **Given** 用户首次登录（无历史游玩记录）
- **When** 用户进入首页
- **Then** 展示引导页面第 1 步"选择你感兴趣的题材"（如恋爱/冒险/悬疑），用户选择后进入第 2 步推荐剧本，点击剧本后进入第 3 步开始游戏

#### Scenario: 老用户登录不展示引导

- **Given** 用户非首次登录
- **When** 用户登录成功
- **Then** 直接跳转到游戏首页，不展示引导

### Requirement: 密码找回

**ID**: REQ-006-R05  
**优先级**: P1  

用户忘记密码时，通过邮箱接收重置链接。重置链接有效期 1 小时。

#### Scenario: 用户请求密码重置

- **Given** 用户在登录页点击"忘记密码"
- **When** 用户输入注册邮箱，点击发送重置链接
- **Then** 系统发送密码重置邮件（无论邮箱是否已注册，均提示"如邮箱已注册，将收到重置链接"）

### R/C/U/D 完整性

| 动作 | 是否包含 | 说明 |
| --- | --- | --- |
| Create | 是 | 注册创建账户（邮箱 + OAuth mock） |
| Read | 是 | 登录读取账户信息 |
| Update | 是 | 验证状态变更、密码重置 |
| Delete | 否 | MVP 不做账户删除（需合规评估后补齐） |

### 下游约束

- 需要邮件服务：发送验证邮件和密码重置邮件（第三方邮件服务，见 Q-002）
- 需要 API 契约：注册、登录、验证、token 刷新、OAuth mock 接口
- 需要安全约束：密码哈希存储、JWT/session 管理、防暴力破解
- 需要 OAuth 抽象层：IOAuthProvider 接口，mock 和真实实现共用
- 验收需要真实后端验证：注册持久化、登录鉴权、验证链接有效、mock OAuth 账户创建
- 验收需要浏览器交互：注册表单、登录表单、OAuth 按钮、引导流程
- **安全风险**：账户删除缺失需在上线前补齐（合规要求）
