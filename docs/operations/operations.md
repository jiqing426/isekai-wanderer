# Operations

本文记录部署拓扑、环境变量、健康检查、开发、评审、发布和回滚规则。

## 环境

| 环境 | 用途 | 入口 | 数据源 | 部署方式 | 负责人 |
| --- | --- | --- | --- | --- | --- |
| local | 本地开发 | 待填写 | 本地依赖 | `docker-compose.yml` 或本地命令 | 待填写 |
| staging | 预发布验证 | 待填写 | 预发布数据 | 待填写 | 待填写 |
| production | 生产 | 待填写 | 生产数据 | 待填写 | 待填写 |

## 服务

| 服务 | 模块 | 端口 | 健康检查 | 依赖 |
| --- | --- | --- | --- | --- |
| backend | `backend/` | `8080` | 待填写 | 数据库、缓存 |
| frontend | `frontend/` | `3000` | 待填写 | backend |
| admin | `admin/` | `3100` | 待填写 | backend |

## 配置

配置示例维护在根目录 `.env.example`。真实配置必须通过本地 `.env`、CI/CD Secret、密钥管理系统或部署平台注入。

| 变量 | 用途 | 默认值 | 必填 | 敏感 |
| --- | --- | --- | --- | --- |
| `APP_ENV` | 运行环境 | `development` | 是 | 否 |
| `DATABASE_URL` | 数据库连接 | 无 | 按项目 | 是 |
| `REDIS_URL` | 缓存连接 | 无 | 按项目 | 否 |
| `JWT_SECRET` | 签名密钥 | 无 | 按项目 | 是 |

## 本地开发

1. 从 `.env.example` 创建本地 `.env`。
2. 安装项目实际技术栈依赖。
3. 启动依赖服务，例如数据库和缓存。
4. 通过 `scripts/dev.sh` 启动目标模块。
5. 修改代码前阅读相关模块 README 和对应 docs。

## 分支和提交

- 分支命名应体现任务类型和范围。
- 提交应聚焦单一目的，避免混入无关格式化。
- 不提交真实密钥、构建产物、临时文件或生产数据。
- 跨模块变更应在提交或 PR 说明中列出影响范围。

## 代码评审

评审至少检查：

- 是否符合模块边界。
- 是否有当前 CR 的 `tasks.md` 任务单和允许写入范围。
- 是否有 Agent Run Log、验证记录和文档同步记录。
- P0/P1 验收项是否更新当前 CR 的 `acceptance.md`。
- 是否改变 API、数据库、权限、部署或用户可见行为。
- 是否有必要测试。
- 是否同步文档。
- 是否引入安全、数据、兼容性或生产风险。

## 发布规则

- 生产发布前执行 `../../deploy/production-checklist.md`。
- 发布必须有版本、负责人、验证步骤和回滚方案。
- 数据库迁移和应用发布顺序必须明确。
- 发布后检查健康状态、日志、错误率和关键业务路径。
- 发布完成后更新功能状态、发布记录和必要的运维说明。

## 回滚规则

- 保留可回滚的镜像、制品或版本标签。
- 不可逆迁移必须提前记录补偿方案。
- 回滚后重新验证 API、前端、管理端和后台任务。

## 文档同步

- 架构变化同步 `../architecture/architecture.md`。
- API 变化同步 `../api/api.md`。
- 数据库变化同步 `../database/database.md`。
- 功能状态变化同步 `../status/feature-status.md`。
- 部署、环境变量、发布或回滚变化同步本文。
- 测试策略变化同步 `../testing/testing.md`。
- AI 协作规则变化同步 `../ai/ai-collaboration.md`；项目级 skill 变化同步 `../../skills/README.md` 或对应 skill 的 `SKILL.md`。
- 重要取舍写入 `../decisions/decisions.md`。
