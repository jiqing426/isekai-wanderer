# Admin

## 模块职责

`admin/` 负责内部管理后台，包括运营工作台、审核配置、权限敏感操作、数据查询、人工处理流程和管理端 API 调用。

管理端默认高风险：任何修改都应考虑权限、审计、误操作保护、数据脱敏和操作回滚。

## 启动方式

推荐通过统一脚本启动：

```sh
../scripts/dev.sh admin
```

项目落地后，应在本模块补充实际命令，例如 `npm run dev`、`pnpm dev`、`yarn dev` 或框架等价命令。

## 目录约定

- `src/`：管理端源代码。
- `tests/`：模块内组件测试、权限展示测试和管理流程测试。
- `public/`：静态资源。
- `docs/`：仅放管理端模块内部说明；跨模块事实写入根部 `docs/`。

未使用的目录可以暂不创建，但创建后必须补充 README 或等价说明。

## 开发规范

- 权限、审计、危险操作确认和数据脱敏要求必须与后端契约一致。
- 管理端功能变化同步 `../docs/status/feature-status.md`。
- 管理端 API 变化同步 `../docs/api/api.md`。
- 不在管理端实现后端权限规则的最终裁决。
- 不展示或记录真实密钥、完整敏感字段或生产凭据。

## 测试方式

推荐通过统一脚本运行：

```sh
../scripts/test.sh admin
```

涉及权限、审核、批量操作、配置变更或数据导出的修改，应补充拒绝路径、边界条件和误操作保护测试。
