# S003 跨会话角色记忆

## REQ-003: 跨会话角色记忆

### 需求概述

角色能"记住"玩家跨会话的关键交互。使用向量数据库存储记忆，高置信度（相似度 >0.8）时召回，不确定时不提及。记忆对用户透明运作（MVP 不做用户可见的记忆管理页面，见 Q-004）。

### Requirement: 记忆存储

**ID**: REQ-003-R01  
**优先级**: P0  

玩家与角色的每次关键交互后，系统提取记忆摘要并存入向量数据库。记忆包含：用户 ID、角色 ID、记忆文本、嵌入向量、创建时间、置信度衰减权重。

#### Scenario: 玩家告诉角色一个个人信息

- **Given** 玩家在与角色 A 对话中说"我最喜欢的花是向日葵"
- **When** 对话轮次结束
- **Then** 系统提取该信息为一条记忆，存入向量数据库，关联用户 ID + 角色 A

#### Scenario: 非关键对话不产生记忆

- **Given** 玩家与角色 A 进行日常寒暄"你好""今天天气不错"
- **When** 对话轮次结束
- **Then** 系统不提取记忆（无有信息量的内容）

### Requirement: 记忆召回

**ID**: REQ-003-R02  
**优先级**: P0  

角色在生成对话时，系统检索相关记忆并注入上下文。仅召回相似度 >0.8 的记忆；多条匹配时按相似度排序取 top-3。

#### Scenario: 角色主动提及之前记住的信息

- **Given** 玩家之前告诉角色 A "我最喜欢的花是向日葵"，当前对话上下文涉及"礼物"话题
- **When** AI 生成角色 A 的对话
- **Then** 角色 A 可能说"我记得你喜欢向日葵，这个送给你"，记忆自然融入对话

#### Scenario: 无高置信度匹配时不提及记忆

- **Given** 当前对话话题与已存储记忆无高相关性（相似度均 <0.8）
- **When** AI 生成角色对话
- **Then** 角色不提及任何记忆内容，正常对话

### Requirement: 记忆摘要压缩

**ID**: REQ-003-R03  
**优先级**: P1  

当单用户单角色的记忆条目超过阈值时，系统自动将旧记忆合并为摘要，减少存储和检索开销。

#### Scenario: 记忆合并压缩

- **Given** 用户 X 与角色 A 已累积 50 条记忆
- **When** 系统执行记忆压缩任务
- **Then** 旧记忆被合并为摘要（如"玩家喜欢花、猫和甜食"），原始条目可标记为已压缩

### 不做范围（本 CR）

- 不做用户可见的记忆回顾/管理页面（见 Q-004，建议 MVP 不做）
- 不做记忆删除功能
- 不做跨角色记忆共享

### R/C/U/D 完整性

| 动作 | 是否包含 | 说明 |
| --- | --- | --- |
| Create | 是 | 对话后自动提取并存储记忆 |
| Read | 是 | AI 生成对话时检索相关记忆 |
| Update | 是 | 记忆摘要压缩（P1，MVP 可简化） |
| Delete | 否 | MVP 不删除记忆 |

### 下游约束

- 需要向量数据库选型确认（PRE-02）
- 需要 AI 集成：记忆提取 prompt、记忆注入 prompt
- 需要 API/DB 契约：记忆存储结构、检索接口
- 验收需要真实后端验证：跨会话记忆持久化、召回精度
- 验收需要 AI 输出验证：记忆自然融入对话、无幻觉
